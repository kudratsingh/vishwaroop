# BLOCKER — WO-001 simulator steps have no machine to run on

**Date:** 2026-10-31 · **Author:** claude-code-vishwaroop · **Work order:** WO-001 · **Phase:** M0
**Rule:** `AGENTS.md §12`; WO-001 stop conditions.

## What was attempted
Running ManiSkill3 for free on the owner's Mac (M3 Pro, 36 GB, Darwin 25.5.0), in a throwaway environment outside this repository, with no system changes. `PROGRAM.md §9` says ManiSkill3 does not run on the Macs. Two ManiSkill documents say otherwise:
- `mani_skill` 3.0.1 package metadata: "MacOS / Anything" is marked as supported for CPU simulation and rendering, and not for GPU simulation.
- [ManiSkill's macOS install guide](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/macos_install.html), read 2026-10-31: CPU simulation is supported after installing the Vulkan SDK. It recommends the Mac for inference, local debugging and developing custom tasks, and a CUDA GPU machine for visual data generation and RL training.

## What happened (measured)
Commands, in an empty scratch directory:
```bash
uv venv -p 3.11 venv
VIRTUAL_ENV=venv uv pip install "mani_skill==3.0.1"
venv/bin/python probe.py PickCube-v1 PickCubeSO100-v1
```
`probe.py` tried, for each task, with and then without `render_backend="none"`:
```python
env = gym.make(env_id, obs_mode="state_dict", control_mode="pd_joint_pos",
               render_mode=None, sim_backend="physx_cpu", **kw)
```

| Step | Result |
|---|---|
| Install on Python 3.11.15 | worked: `mani_skill` 3.0.1, `sapien` 3.0.3, `torch` 2.15.0, `numpy` 2.4.6, `gymnasium` 1.4.0 |
| `import sapien`, `import mani_skill` | worked |
| SO-100 URDF and meshes | present in the package |
| `gym.make(...)`, all four combinations | **failed** |

The log, with its timestamps removed:
```text
WARNING - Detected MacOS system, forcing render backend to be sapien_cpu and render device to be MacOS compatible.
[svulkan2] [error] Your GPU driver does not support Vulkan. You may not use the renderer for rendering.
RuntimeError: vk::createInstanceUnique: ErrorIncompatibleDriver
```
`mani_skill/envs/utils/system/backend.py` forces that backend on macOS whatever is requested, so `render_backend="none"` cannot help there. The machine has no Vulkan driver.

The agent then tried to download Khronos's MoltenVK release into a scratch directory and point `VK_ICD_FILENAMES` at it, which changes nothing system-wide. The agent's permission system declined downloading and running that binary, and the agent did not look for another way around it.

**Not run:** any simulator episode on any machine. So ET-M0-2, ET-M0-3 and ET-M0-4 have no evidence, and whether a Vulkan driver would be enough on this Mac is unknown.
