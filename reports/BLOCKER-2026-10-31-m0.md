**Rule:** `AGENTS.md §12`; WO-001 stop conditions.

## What was attempted
Running ManiSkill3 for free on the owner's Mac (M3 Pro, 36 GB, Darwin 25.5.0), in a throwaway environment outside this repository, with no system changes. `PROGRAM.md §9` says ManiSkill3 does not run on the Macs. ManiSkill's own documents disagree with each other on this, so it was tested.

## What happened (measured)
| Step | Result |
|---|---|
| `uv pip install mani_skill==3.0.1` on Python 3.11.15 | worked: `sapien` 3.0.3, `torch` 2.15.0, `numpy` 2.4.6, `gymnasium` 1.4.0 |
| `import sapien`, `import mani_skill` | worked |
| SO-100 URDF and meshes | present in the package |
| `gym.make("PickCubeSO100-v1", ..., sim_backend="physx_cpu")` | **failed**: `vk::createInstanceUnique: ErrorIncompatibleDriver` |

ManiSkill logs that on macOS it forces its CPU render backend, and that backend needs Vulkan even for state-only runs. `render_backend="none"` did not avoid it. The machine has no Vulkan driver. ManiSkill's macOS guide says to install the Vulkan SDK, which provides MoltenVK.

The agent then tried to download Khronos's MoltenVK release into a scratch directory and point `VK_ICD_FILENAMES` at it, which changes nothing system-wide. The agent's permission system declined downloading and running that binary, and the agent did not look for another way around it.

**Not run:** any simulator episode on any machine. So ET-M0-2, ET-M0-3 and ET-M0-4 have no evidence, and whether a Vulkan driver would be enough on this Mac is unknown.
